# Hướng Dẫn Vận Hành & Cấu HÌnh GitLab CI/CD Đa Chi Nhánh (Star-Bash Suite)

Tài liệu này hướng dẫn chi tiết các bước cần thiết để thiết lập và tích hợp quy trình CI/CD tự động lên VPS cho cả dự án **Frontend (Next.js / PM2)** và **Backend (Docker / Docker Compose)** đã được cấu hình trước đó bằng Star-Bash Suite.

---

## I. KIẾN THỨC NỀN TẢNG VỀ QUY TẮC NHÁNH (CRITICAL NOTE)

Hệ thống Star-Bash thế hệ mới sử dụng cơ chế **Ánh xạ biến môi trường động theo nhánh**. Tên của các biến cấu hình trên GitLab CI/CD Variables **bắt buộc** phải khớp với tên chi nhánh mà bạn cấu hình chạy CI/CD theo công thức viết hoa.

> [!IMPORTANT]
> **Công thức đặt tên biến môi trường:**
> * Biến `.env` chung: `ENV_LOCAL_<TÊN_NHÁNH_VIẾT_HOA>`
> * Biến `.env.docker` (BE): `ENV_DOCKER_<TÊN_NHÁNH_VIẾT_HOA>`

### Bảng ví dụ ánh xạ tên biến theo nhánh:

| Tên chi nhánh (Git Branch) | Biến cấu hình chung (Type: File) | Biến cấu hình Docker (Type: File) |
| :--- | :--- | :--- |
| **`main`** hoặc **`master`** | `ENV_LOCAL_MAIN` hoặc `ENV_LOCAL_MASTER` | `ENV_DOCKER_MAIN` hoặc `ENV_DOCKER_MASTER` |
| **`develop`** | `ENV_LOCAL_DEVELOP` | `ENV_DOCKER_DEVELOP` |
| **`staging`** | `ENV_LOCAL_STAGING` | `ENV_DOCKER_STAGING` |
| **`feature/payment`** | `ENV_LOCAL_FEATURE_PAYMENT` | `ENV_DOCKER_FEATURE_PAYMENT` |

*(Lưu ý: Tất cả các ký tự đặc biệt như dấu gạch chéo `/` hoặc gạch ngang `-` trong tên nhánh sẽ được tự động chuyển đổi thành dấu gạch dưới `_` khi mapping).*

## II. HƯỚNG DẪN CẤU HÌNH CHO DỰ ÁN FRONTEND (Next.js / PM2)

### 1. Các bước cần thực hiện trên VPS ban đầu
1. Truy cập vào menu quản lý dự án trên VPS: `bash run.sh` -> Chọn mục **[4] Quản lý Dự án** -> Chọn dự án FE cần thiết lập.
2. Chọn phím **`[8]`** để sửa đổi phân quyền thư mục mã nguồn sang user `deployer:deployer` (Bắt buộc).
3. Chọn phím **`[4]`** để tự động sinh tệp tin cấu hình `.gitlab-ci.yml` đa chi nhánh động.
4. Chọn phím **`[1]`** trong menu Quản lý dự án để hệ thống tự động chạy Next.js ban đầu bằng tài khoản `deployer`.

### 2. Cấu hình biến môi trường trên GitLab CI/CD
Truy cập vào repo dự án trên GitLab UI: **Settings > CI/CD > Variables** và thêm đầy đủ các biến sau:

| Tên biến | Kiểu (Type) | Giá trị (Value) | Mô tả |
| :--- | :--- | :--- | :--- |
| **`VPS_IP`** | `Variable` | IP Public của VPS | Địa chỉ IP của máy chủ VPS nhận deploy. |
| **`SSH_PRIVATE_KEY`** | `Variable` | Nội dung SSH Private Key | Lấy từ tệp `/home/deployer/.ssh/id_rsa_gitlab` trên VPS (hoặc hiển thị bằng tuỳ chọn số `[6]` trong Project Manager). |
| **`ENV_LOCAL_DEVELOP`** | `File` | Nội dung tệp `.env.local` | Cấu hình môi trường chạy bản thử nghiệm (`develop`). |
| **`ENV_LOCAL_MAIN`** | `File` | Nội dung tệp `.env.local` | Cấu hình môi trường chạy bản chính thức (`main`). |

## III. HƯỚNG DẪN CẤU HÌNH CHO DỰ ÁN BACKEND (Docker / Docker Compose)

### 1. Vị trí và Nội dung tệp tin `scripts/deploy.sh`
Để thư mục gốc dự án sạch sẽ và đồng bộ trên Git, tệp lệnh triển khai Docker Compose được quy chuẩn lưu tại đường dẫn: **`scripts/deploy.sh`**.

> [!TIP]
> Tệp này phải được commit và push lên Git repository để khi GitLab CI/CD kéo code mới về, nó sẽ thực thi chính xác phiên bản lệnh mới nhất.

#### Nội dung tiêu chuẩn của `scripts/deploy.sh`:
```bash
#!/bin/bash
# ==============================================================================
# Auto-generated by Star-Bash Suite
# Description: Custom deployment runner for Backend Docker services
# ==============================================================================
echo "==> [Docker Deploy] Khởi chạy dịch vụ container..."

# Sử dụng đồng thời cả 2 file môi trường đã được GitLab CI/CD tự sinh ra trước đó
docker compose --env-file .env --env-file .env.docker -f docker-compose.yml -f docker-compose.prod.yml up -d --build

# Dọn dẹp các Docker image rác không còn sử dụng để tiết kiệm tài nguyên VPS
docker image prune -f
```

### 2. Các bước cần thực hiện trên VPS ban đầu
1. Truy cập Project Manager: `bash run.sh` -> Chọn mục **[4]** -> Chọn dự án BE.
2. Chọn phím **`[8]`** để sửa phân quyền thư mục sang `deployer:deployer` (Bắt buộc để GitLab Runner SSH vào không bị lỗi quyền).
3. Chọn phím **`[4]`** để tự sinh tệp tin cấu hình `.gitlab-ci.yml` Backend phiên bản SSH Git Pull tối ưu.
4. Đảm bảo mã nguồn trên máy của bạn đã được cấu hình thư mục `scripts/` chứa tệp `deploy.sh` nêu trên và đã đẩy lên Git.

### 3. Cấu hình biến môi trường trên GitLab CI/CD
Truy cập vào repo dự án trên GitLab UI: **Settings > CI/CD > Variables** và thêm đầy đủ các biến sau:

| Tên biến | Kiểu (Type) | Giá trị (Value) | Mô tả |
| :--- | :--- | :--- | :--- |
| **`VPS_IP`** | `Variable` | IP Public của VPS | Địa chỉ IP của máy chủ VPS nhận deploy. |
| **`SSH_PRIVATE_KEY`** | `Variable` | Nội dung SSH Private Key | Dùng để kết nối SSH an toàn vào VPS. |
| **`ENV_LOCAL_DEVELOP`** | `File` | Nội dung tệp `.env` | File môi trường gốc cho nhánh `develop` (chứa các biến của ứng dụng). |
| **`ENV_DOCKER_DEVELOP`** | `File` | Nội dung tệp `.env.docker` | File môi trường phục vụ cấu hình Docker cho nhánh `develop`. |
| **`ENV_LOCAL_MAIN`** | `File` | Nội dung tệp `.env` | File môi trường gốc cho nhánh `main`. |
| **`ENV_DOCKER_MAIN`** | `File` | Nội dung tệp `.env.docker` | File môi trường phục vụ cấu hình Docker cho nhánh `main`. |

## IV. LƯU Ý BẢO MẬT & VẬN HÀNH

> [!WARNING]
> **Quyền hạn của user `deployer`:**
> * Đối với Frontend, PM2 của dự án bắt buộc phải khởi động lần đầu bằng quyền user `deployer` (sử dụng tùy chọn `[1]` trong Menu quản lý dự án). Nếu chạy bằng `root`, GitLab CI/CD của deployer sẽ không có quyền reload hay restart.
> * Đối với Backend, user `deployer` phải thuộc nhóm `docker` trên VPS để thực thi lệnh chạy Docker không cần quyền sudo (`usermod -aG docker deployer`). Lệnh này đã được Star-Bash tự động thiết lập sẵn khi bạn khởi tạo dự án bằng tool.
